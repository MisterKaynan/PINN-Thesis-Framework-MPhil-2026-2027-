# Resumable PINN Experiments for Sparse COVID-19 Surveillance Data

Thesis: *Physics-Informed Neural Networks for Infectious-Disease Modelling under Ghanaian Surveillance Constraints: An Adaptation of Millevoi et al.'s Compartmental Model* — Atua-Ntow, 2026/2027.

This project compares reduced-SIR physics-informed neural networks trained jointly (`pinn_joint`) or in two stages (`pinn_split`). Ghana provides an authentic reporting-mask experiment; Italy-primary provides a short single-wave comparator; Italy-secondary provides a separately reported multi-wave robustness experiment.

Research and education only. Model outputs are not operational public-health estimates or clinical advice.

## Documentation status

This README consolidates the preprocessing, analysis, plotting and troubleshooting changes reviewed through 24 November 2026. It documents the intended corrected workflow, not a certification that every local script or saved result already implements it.

Several versions of scripts and notebooks have circulated. Use `python src/<script>.py --help` to check the installed interface before running commands. In particular, the stage wrapper, checkpoint sidecars, hospitalisation runner and statistical-test features must be checked against the current checkout. A corrected figure does not establish that old forecasting results were regenerated.

## Study arms and target construction

| Label | Purpose | Target / observation design |
|---|---|---|
| `ghana` | Core surveillance-constraint experiment | Five-day trailing incidence proxy; daily, weekly and reporting-mask regimes |
| `italy_primary` | Core single-wave comparison | Five-day trailing proxy from incidence adjusted by the declared factor r=6; daily, weekly and controlled dropout regimes |
| `italy_secondary` | Within-arm multi-wave robustness | Five-day trailing proxy from raw reported incidence throughout the series; no ascertainment adjustment in the canonical workflow |

Never pool Italy arms under a generic `italy` label. Ghana's reporting-mask mechanism is not equivalent to Italy's random dropout. Country-level differences do not isolate a causal effect of surveillance quality.

The five-day trailing proxy is an approximation to the infectious state, not a directly observed count of currently infectious people. Ghana's daily-incidence data-quality panel and Italy's rolling-proxy panels are not directly comparable in magnitude or smoothness.

Use a dedicated environment containing NumPy, pandas, SciPy, Matplotlib and PyTorch. Record exact Python/package versions and the code revision. Install the appropriate PyTorch build for the intended device; CPU/GPU availability and fit speed must be measured rather than assumed.

Run commands from the repository root. Keep raw data and expensive results backed up.

### Italy-primary

```bash
python src/prepare_italy.py --arm primary --ascertainment fixed --input data/raw/italy_case_hosp.csv --outdir data/processed
```

The configured primary window is 20 February–20 May 2020, comprising 91 daily rows. The r=6 correction and its validity assumptions must be declared; the phrase “single-wave benchmark” does not imply error-free surveillance or exact replication of every published setting.

### Italy-secondary: canonical corrected workflow

```bash
python src/prepare_italy.py --arm secondary --ascertainment none --input data/raw/italy_case_hosp.csv --outdir data/processed
```

Back up existing outputs first. Pass `--overwrite` only when the installed script supports it and replacement is intentional.

The secondary target must retain raw reported incidence throughout the full selected period. Do not:

- represent an undefined ascertainment correction as zero infections;
- apply an unsupported fixed correction across the entire multi-wave period;
- splice r=6-adjusted and raw values into one continuous fitting target without modelling and disclosing the scale break;
- use illustrative time-varying ascertainment ratios as established estimates.

The reviewed source contained a bug in which post-cutoff correction NaNs became zeros. The corrected workflow removes that artificial tail. Restricted-window analysis is separate: the correction package truncates it at the configured validity cutoff; it is not the canonical full-range secondary experiment.

After any master regeneration:

1. Recreate arm-specific sparse masks using the installed `sparsify.py` interface.
2. Inspect the audit and verify `I_proxy` equals the D=5 trailing sum of the intended incidence input.
3. Check source-row coverage and any explicit imputation.
4. Run experiments into new result paths; do not resume incompatible old checkpoints.

Use `python src/sparsify.py --help` before invoking it: circulated versions differ in their output and in-place options.

## Forecast experiment protocol

Each fit uses a declared training window and forecasts a complete following horizon. For a 91-row primary master and a 15-day horizon, origins 90 and 105 are infeasible.

A proposed harmonized primary origin set is `65 70 75`. Earlier grids used `45 60 75` or other sets. Choose one protocol explicitly; do not claim historical outputs used the new origins. Check weekly sample counts and runner minimum-observation rules. With a 15-day horizon, these closely spaced origins also yield overlapping forecast windows.

Example Ghana command:

```bash
python src/run_ghana.py --master data/processed/ghana_national_master.csv --out results/tables/grid_ghana_new_run.csv --origins 65 70 75 --horizon 15 --regimes daily weekly mask --modes split joint --seeds 1 2 3
```

For Italy, check `run_italy.py --help` or the reviewed wrapper before constructing the equivalent command. Country CLI support differs across circulated versions. Verify that output rows identify `italy_primary` or `italy_secondary` explicitly.

For secondary robustness, select origins across the corrected series, not only early 2020. A master ending in 2022 is not evidence of a multi-wave forecasting evaluation if all forecast origins remain in 2020. Every origin must leave a complete horizon.

Use training-only normalization and metric denominators in a final forecasting implementation. The historical Ghana runner computed its neural target scale from the full series; audit the current implementation before making a strict leakage-free evaluation claim.

### Legacy labels

The plotting CLI rejects generic `italy` labels by default. After manually verifying each file's arm, `--allow-legacy-italy-label` explicitly assigns labels according to its input flag and prints the migration. This does not establish that a file was trained on the correct master.

### Metrics and interpretation

Pair non-daily and daily fits on country, method, origin and seed, within a fixed run and horizon.

- Signed MASE gap = non-daily MASE minus daily MASE.
- Percentage gap = 100 times the signed gap divided by daily MASE.
- Positive means deterioration; negative means improvement.
- A zero daily denominator makes percentage degradation undefined; retain the signed difference.
- Median paired percentage gaps are not ratios of aggregate median MASE values.
- Across-seed IQR describes seed variability, not independent uncertainty across epidemic trajectories.

For direct split-versus-joint conclusions, match their origin/seed coverage too. Weekly and daily summaries may otherwise cover different origin sets. Report paired sample counts and origin-level results.

MASE in the reviewed runner uses the mean absolute first difference of the training target as denominator. MASE below one does not automatically show superiority to an actual held-out persistence baseline; compare the saved baseline forecast errors directly.

Random-dropout improvements are descriptive findings, not proof that missing data helps. Repeat mask realizations before claiming a stable dropout-response relationship. “Observation-regime sensitivity” is a safer description than a causal equity gap.

## Auxiliary hospitalisation ablation

Keep the infection-only model primary. Ghana's auxiliary hospitalisation signal is model-derived, not observed. In the intended corrected generator, admissions inflow and occupancy are distinct outputs; only admissions inflow is comparable in channel meaning to daily admissions.

The shared-trunk auxiliary H head supervises a second output while retaining the reduced I/R_t residual. It does not implement the full coupled hospitalisation model from Millevoi et al. or reproduce the full Dwomoh SEIQHRS system. A reduced Q equation omitting E and a rolling infectious approximation must be declared as assumptions.

Check `synth_hospitalisation.py --help` and the dedicated ablation runner's presence before use. Older attached generators used an occupancy output and lagged-Q approximation. Do not describe those old outputs as corrected admissions. Report H scaling, scenario assumptions, training-window restrictions and provenance. Use synthetic H only for a separately labelled sensitivity analysis.

## Statistical analysis

Keep primary and secondary separate in `equity_metrics.py` and `stat_tests.py`. Check each CLI and inspect the implementation before relying on documented tests, log-gap exports, epsilon thresholds or origin-clustered aggregation: those features differ across versions.

Seeds are repeated fits, not independent epidemic realizations. Nearby forecast windows overlap. Cross-country comparisons remain confounded by source, target construction and epidemic timing. Report effect sizes, paired counts and exploratory status rather than asserting significance from bar heights.

## Windows rendering and runtime diagnostics

Observed issues included two distinct native failures:

1. OpenMP Error #15: duplicate initialization of `libiomp5md.dll` in the training/base environment.
2. Fatal exception `0xc06d007f` during a minimal Agg `savefig` test in a plotting environment. Imports, figure creation and adding a line succeeded; rendering failed before PNG creation.

These are not duplicate-label pandas errors. Removing explicit NumPy calls or combining methods does not remove Matplotlib's native dependencies. Separate-process plotting preserves the notebook kernel but does not guarantee that the child process can render.

Before modifying scientific calculations:

1. Inspect captured stdout, stderr and return code; `check_returncode()` reports an earlier failure rather than causing it.
2. Open Anaconda Prompt, activate the plotting environment, and run a minimal PNG rendering test.
3. If activated execution works but a direct notebook child fails, test `conda run -n pinn-plots --no-capture-output python ...` to supply environment-aware launching.
4. Set `matplotlib.use("Agg")` before importing pyplot for file-only scripts. It avoids GUI rendering, not all native dependencies.
5. Enable `-X faulthandler` and flushed progress messages around figure creation, layout and save.
6. Use a fresh output directory after partial runs. A directory containing only CSVs does not establish successful figure generation.
7. If a fully activated minimal test still fails, collect dependency versions and investigate the environment independently of the experiment code.

Do not manually delete DLLs, enable `KMP_DUPLICATE_LIB_OK=TRUE` for scientific production, or install training dependencies merely to run plotting-only cells. No universal fix for the native failure is claimed here.

## Reproducibility and migration checklist

- Back up processed data and outputs before replacing them.
- Verify the current `--help` for each script and wrapper.
- Rebuild secondary from raw incidence across the full selected window.
- Regenerate masks, audits and experiments after master changes.
- Do not splice old/new secondary fits without a dependency audit.
- Validate the shared PINN engine and record accuracy as well as time.
- Match origins, horizon, mode and seeds explicitly for each comparison.
- Use later secondary origins if claiming multi-wave forecast robustness.
- Preserve exact input hashes, code revision, configuration and environment.
- Keep plotting CSVs and figure input manifests with final figures.
- Do not treat newly rendered figures as evidence of new model fits.
- Keep cloud checkpoint products on persistent storage.
