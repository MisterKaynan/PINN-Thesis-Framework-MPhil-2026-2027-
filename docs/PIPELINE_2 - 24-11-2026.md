# MPhil Experimental Pipeline: Split/Joint Reduced-SIR PINNs

Updated: 24 November 2026.

This document describes the corrected execution order for Ghana, Italy-primary and Italy-secondary experiments. The README provides the project overview; this document specifies stage inputs, outputs, checks and invalidation rules.

## 0. Scope, implementation status and scientific boundaries

The primary method comparison is `pinn_split` versus `pinn_joint`. Ghana represents a reporting-mask experiment; Italy-primary is a single-wave comparator; Italy-secondary is a separately reported multi-wave robustness extension. Synthetic Ghana hospitalisation is an optional auxiliary-supervision sensitivity analysis.

This is the intended corrected protocol, not confirmation that every local checkout and existing result implements it. Multiple script versions have circulated. Before execution:

```bash
python src/prepare_italy.py --help
python src/sparsify.py --help
python src/run_ghana.py --help
python src/run_italy.py --help
python src/checkpoint_grid_runner.py --help
python src/fig_degradation_equity.py --help
python src/extract_rt.py --help
```

Check optional files exist before invoking them. Do not infer supported flags, identity checks, statistical aggregation or auxiliary-target semantics from an older document.

The reduced-SIR PyTorch implementation is an adaptation, not the unchanged published implementation. Benchmark validation does not establish that the full real-data model, hospitalisation formulation or extrapolation protocol exactly reproduces the paper.

### Questions and supported evidence

| Question | Evidence | Limits |
|---|---|---|
| What observation constraints are present? | Raw-data audit, mask audit, coverage/proxy figure | Zero-based reporting classification is a rule, not independent verification of every missing report. |
| How do split and joint compare? | Matched forecast-origin/seed results under a fixed regime | Different completed-fit coverage must not be silently pooled. |
| How sensitive are methods to observation regimes? | Paired non-daily vs daily MASE differences | Random dropout, weekly sampling and clustered reporting gaps are different mechanisms. |
| Does performance vary across settings? | Separately labelled arm-level descriptive results | Country, target construction and epidemic phase confound cross-country interpretation. |
| How does the method behave over multiple waves? | Corrected secondary master and forecast origins spanning its period | A long master alone is not a multi-wave forecasting evaluation. |
| What R_t trajectories does the model learn? | Fresh full-series R_net fits and appropriate external comparisons | Model-derived trajectories are not official estimates or operational decision utility. |
| Does an auxiliary channel alter behaviour? | Paired infection-only vs synthetic-admissions ablation | Synthetic H adds assumptions, not independent observed Ghana hospital data. |

ECE, CRPS, calibrated uncertainty, peak-timing error and decision-utility claims are not assumed implemented. Across-seed point-error spread alone is not a calibrated predictive distribution. Those analyses require explicit outputs, definitions and validation before inclusion.

## 3. Stage 1 — Raw data and preprocessing

### 3.1 Ghana

Use the actual source filename, for example:


The primary mask classifies zero national incidence as unobserved. Report this rule and examine the contextual sensitivity mask. The reviewed image's 117 days (27.0%) and maximum 14-day gap describe that snapshot and mask, not universal constants.

### 3.3 Italy-primary

```bash
python src/prepare_italy.py --arm primary --ascertainment fixed --input data/raw/italy_case_hosp.csv --outdir data/processed
```

The configured primary period is 20 February–20 May 2020, with 91 daily rows. The declared r=6 adjustment is applied before constructing the trailing five-day proxy. This is an experimental assumption, not an assertion that all observations are complete or error-free.

### 3.4 Italy-secondary: canonical full-range configuration

```bash
python src/prepare_italy.py --arm secondary --ascertainment none --input data/raw/italy_case_hosp.csv --outdir data/processed
```

Use raw reported incidence consistently throughout the selected range. The reviewed snapshot runs from 29 January 2020 to 23 October 2022, but actual dates must come from the source/audit.

An older workflow set adjusted incidence to NaN after a validity cutoff, then zero-filled it. That produced a false flat tail. Another version switched from r=6 to raw counts at the cutoff, introducing an artificial scale break. Neither is the canonical secondary target.

The supplied correction package defines `restrict` as truncation at the configured cutoff. Earlier attached code used different semantics. Verify the installed behaviour; do not use `restrict` as a substitute for a continuous full-range raw-incidence experiment.

### Outputs and acceptance gate

Each Italy arm should have a master, weekly product, reference-format export and audit. Back up existing products before intentional overwrite.

Verify:

- Valid, unique, ordered daily dates and an explicit missing-day policy.
- Finite, non-negative intended training targets.
- Country labels `ghana`, `italy_primary`, `italy_secondary` remain distinct.
- Secondary I_proxy equals the D=5 trailing sum of raw reported incidence.
- No undefined correction has been silently represented as zero cases.

### 6.1 Freeze a feasible design

A proposed harmonized primary set is origins `65 70 75`, horizon 15, seeds `1 2 3`, both methods. Historical outputs used other sets, including `45 60 75`; a README edit does not change those results.

For a 91-row primary series, origins 90 and 105 leave no complete 15-day horizon. Check weekly observation counts and runner minimum-data rules. Origins 65, 70 and 75 yield overlapping forecast windows; treat dependence explicitly.

| Italy-primary | daily, weekly, sparse20, sparse30, sparse40 | Core single-wave comparison |

## 7. Stage 5 — Assemble and audit results

Minimum analysis fields:

```text

```

Also retain horizon, MAE, RMSE, training count and timing where available. Keep source/master/mask hashes, code revision and environment in the run manifest.

Reject duplicate `(country, method, origin, seed, regime)` keys within a fixed run/horizon. A conflicting fit is not resolved by averaging it away. Missing completed modes or seeds should be visible in coverage tables.

Generic `italy` labels in historical files may be migrated only after verifying each file's arm. The explicit plotting flag logs this migration; it does not verify the master used for training.

Do not silently reload stale `grid.csv`, `grid_italy.csv`, `italy_grid.csv` or old equity summaries when new files were intended.

## 8. Stage 6 — Paired degradation metrics

For each country/method/regime, pair non-daily and daily errors by origin and seed within a fixed protocol.

- Signed gap: `mase_regime - mase_daily`.
- Percentage gap: `100 * (mase_regime - mase_daily) / mase_daily`.
- Positive indicates degradation, negative indicates improvement.
- With daily MASE zero, percentage gap is undefined; preserve the signed difference.
- Report unmatched counts and the number of valid pairs.

Aggregate per-pair gaps, not a ratio of independently aggregated medians. These are different statistics and may differ in sign when coverage or relative effects differ.

MASE in the reviewed runner scales held-out absolute error by the mean absolute training-target first difference. A value below one is not automatic proof of outperforming an actual held-out persistence forecast. Compare baseline result rows directly.

Use `equity_metrics.py --help` for the installed interface. The corrected package reports paired gaps and across-seed spread and keeps secondary separate. Do not assume ECE, CRPS, log gaps, audit manifests or a common-origin country filter are implemented merely because older documentation listed them.

For split-versus-joint claims, also restrict to shared origin/seed keys within each regime. This additional method pairing is not automatically guaranteed by within-method daily pairing.

## 10. Stage 8 — Fresh full-series PINN R_t fits

```bash
python src/extract_rt.py --master data/processed/ghana_national_master.csv --country ghana --outdir results/rt/new_run --modes split joint --seeds 1 2 3
python src/extract_rt.py --master data/processed/italy_primary_national_master.csv --country italy_primary --outdir results/rt/new_run --modes split joint --seeds 1 2 3
python src/extract_rt.py --master data/processed/italy_secondary_national_master.csv --country italy_secondary --outdir results/rt/new_run --modes split joint --seeds 1 2 3
```

These are fresh neural-network fits, not cheap arithmetic post-processing or forecasting-checkpoint retrieval. Budget and log them separately.

The corrected extractor returns actual learned R_net and fitted I_proxy, rejects inadmissible output rather than concealing it through clipping, and checks secondary target consistency. It writes per-fit trajectories, daily seed summaries and fit summaries, with figure production as a separate rendering step in the reviewed implementation.

Across-seed 10th–90th percentiles describe optimization-seed spread, not an epidemiological confidence interval. Distinguish current daily summaries from historical single-row median files and finite-difference proxies.

Literature points must retain provenance and precision. Visually read values are approximate, not exact ground truth. A few first-wave points cannot validate a full secondary trajectory, and the synthetic hospital channel is not external validation.

## 11. Stage 9 — Optional synthetic hospitalisation ablation

Use only after the primary forecasting workflow is validated.

### Intended corrected design

1. Verify the Ghana D=5 infection proxy against the source incidence.
2. Construct a separately declared approximate infectious input for synthesis, for example the reviewed 14-day trailing approximation.
3. Evolve reduced Q dynamics under declared Dwomoh-derived rates; acknowledge omission of E when no exposed series exists.
4. Export daily admission inflow and occupancy as different quantities.
5. Use daily inflow for an admissions-channel auxiliary target.
6. Pair infection-only and auxiliary-H fits on origin, regime, mode and seed; use training-only channel scales.

Check the installed generator and dedicated runner interfaces before execution. Historical `synth_hospitalisation.py` versions used a lagged-Q approximation and occupancy targets; do not describe them as corrected inflow generation.

The refactored auxiliary PINN uses a shared I/H trunk and normalized H supervision while retaining the I/R_net residual. No hospitalisation ODE is enforced. It is neither a full Dwomoh SEIQHRS simulation nor an exact implementation of Millevoi's coupled hospitalisation model.

Scenario equivalences apply only under the declared reduced/externally driven equations. They must not be generalized to the full coupled epidemic model. Record initial conditions, equations, rate units, scenarios, input hashes and the synthetic origin of the channel.

## 12. Stage 10 — Statistical comparisons and interpretation

Audit `stat_tests.py` before interpreting its output. Where implemented, use paired split/joint comparisons and origin-aware aggregation across seeds. Do not count three seeds as three independent epidemic realizations.

Wilcoxon, Friedman or Mann–Whitney output is not sufficient without checking complete pairs/blocks, sample size, ties, overlapping horizons and country confounding. Any chosen minimum-origin threshold is a reporting rule, not a guarantee of independence or adequacy.

Keep Italy-secondary separate. Report effect sizes, pair counts, origin-level distributions and exploratory status. Do not assert split universally dominates or forecast errors establish intervention effects.

## 13. Runtime and Windows diagnostics

### Distinguish failures

| Symptom | Interpretation / next action |
|---|---|
| `cannot reindex ... duplicate labels` | Preserve method in filters/keys; inspect duplicate result keys. A Python exception, not proof of native failure. |
| `No module named torch` in plotting environment | Training setup was run in a plotting-only environment. Skip it; do not install torch just to plot CSVs. |
| Undefined `RAW`, `ACTIVE_DEVICE`, `JOB_CPU_THREADS`, `plot_data` | Notebook dependency/state failure after incomplete setup. Initialize only the variables the workflow needs. |
| `CalledProcessError` | Inspect child stdout/stderr/return code. The reporting exception is not the original cause. |
| OMP Error #15 | Duplicate OpenMP initialization was reported in the original environment; investigate separately from pandas. |
| `0xc06d007f` during minimal Agg save | Observed native rendering/dependency failure. Exact DLL not established from Python frames alone. |

The minimal Windows test imported NumPy/pandas/Matplotlib, created a figure and added a line, then failed at `savefig`. This rules out the experiment pairing as a necessary trigger. It does not establish that all later environments have the same fault.

### Diagnostic order

1. Activate the plotting environment in Anaconda Prompt and verify `sys.executable` and `CONDA_PREFIX`.
2. Test a two-point PNG using Agg, outside VS Code.
3. If activated execution succeeds, test environment-aware `conda run` rather than direct interpreter launching from a misactivated parent.
4. Enable `-X faulthandler` and print flushed checkpoints around figure creation, layout and saving.
5. Inspect partial outputs and use a fresh directory after failure.
6. If the activated minimal test fails, inspect package provenance/dependencies or test a separate clean environment without modifying the training environment.

For standalone image files, select Agg before pyplot, save, then close the figure; omit interactive `show()`. Both display and saving still require rendering. Separate processes protect the notebook from child failures but do not repair DLL resolution.

Do not delete DLLs manually or use `KMP_DUPLICATE_LIB_OK=TRUE` for production scientific outputs. No universal runtime fix is claimed. Successful updated figures establish rendering for their production workflow, not a blanket environment repair.

## 14. Compute planning

Remove fixed historical wall-clock and expected-accuracy targets from scheduling decisions. Measure a representative full-configuration fit for each mode/arm, including secondary and auxiliary models if used.

Estimate remaining work from actual fit counts and measured throughput, allowing for skipped regimes, differing observation counts, worker contention and restart overhead. Mini-batch update count, not epoch count alone, affects cost. A long full-series R_t fit can be more expensive than a short forecasting window.

Check worker/thread settings and memory use empirically. Avoid oversubscribed CPU workers or multiple processes competing for a small GPU without an explicit plan. Sharding is useful only if result identity and merge checks remain intact.

No scientific ordering of country MASE, monotonic dropout curve or universal split advantage is an acceptance threshold. Results must be measured, not forced toward earlier expectations.

## 15. Invalidation and regeneration matrix

| Change | Required downstream action |
|---|---|
| Raw source, date interpretation or aggregation | Rebuild masters, audits, masks, dependent fits, summaries, R_t and figures. |
| Secondary correction / zero-tail repair | Regenerate secondary master/masks and dependent experiments; do not splice incompatible checkpoints. |
| Mask rule or dropout seed | Regenerate affected mask products, fits and comparisons. |
| Origin/horizon/target/scaling/model changes | New run identity and affected fits; rebuild analyses and figures. |

| Pairing/statistical aggregation change | Recompute summaries/tests and figures from verified fit rows. |
| Runtime environment change | Repeat smoke/benchmark checks and record versions; numerical-equivalence claims require verification. |
